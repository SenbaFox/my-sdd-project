# Feature Specification: ブロック崩しゲーム

**Feature Branch**: `001-breakout-game`  
**Created**: 2025-12-13  
**Status**: Draft  
**Input**: ユーザー要望: "プレイヤーがボードを左右に操作してボールを跳ね返し、8x8のブロックを崩すゲーム。ボールを1つのブロックに2度当てるとそのブロックが崩れる。ボールが画面下部に到達でライフ-1。ライフは3。ブロック崩すたびにスコア加算。5個増すたびにレベルアップでボールスピード上昇。全ブロック崩したらクリア"

---

## User Scenarios & Testing *(mandatory - 憲法準拠)*

**憲法準拠確認**: 全ユーザーストーリーは、以下の原則に準拠する必要があります:
- **コード品質**: 各機能の実装はコード品質原則を満たすこと
- **テスト基準**: 各ストーリーは、独立してテスト可能かつ80%以上のカバレッジを達成すること
- **UX一貫性**: UIはデザインシステムに準拠し、アクセシビリティを考慮すること

---

### User Story 1 - ゲーム画面の表示 (Priority: P1)

プレイヤーはゲーム開始時に、以下の要素が正しく表示されたゲーム画面を見ることができます：
- 8x8のブロックグリッド（画面上部）
- ボードパドル（画面下部、中央）
- ボール（初期位置：ボードの上）
- ライフカウンター（現在：3）
- スコアディスプレイ（現在：0）
- レベルインジケータ（現在：1）

**Why this priority**: ゲームの基本的な見た目が完成しないと、それ以上の機能開発が進められない。このMVPは「画面描画」という最小限の価値を提供する。

**Independent Test**: ゲーム開始時に、8個のブロック行が表示され、ボード、ボール、ライフ/スコア表示がすべて見える状態で、ゲームループが安定して実行できることを確認。

**Acceptance Scenarios**:

1. **Given** ゲーム初期状態, **When** ゲーム開始, **Then** 8x8ブロックグリッド、ボードパドル、ボール、ライフカウンター、スコア、レベルが画面に表示される
2. **Given** ゲーム実行中, **When** 画面の描画, **Then** 60FPS以上で安定して再描画される（レスポンシブなUI）
3. **Given** ゲーム画面表示後, **When** 要素確認, **Then** すべての要素がアクセシブル（色対比、フォントサイズなど）である

---

### User Story 2 - ボード操作 (Priority: P1)

プレイヤーは、キーボード入力（左右矢印キーまたはA/D）でボードパドルを左右に移動させ、ボールをボードの上で跳ね返すことができます。

**Why this priority**: プレイヤーがゲームをコントロールする最小限の機能。これなしには、ゲームとして成立しない。

**Independent Test**: 左右キーを押すと、ボードが対応する方向に移動し、ボールが跳ね返ることを単独で検証できる。

**Acceptance Scenarios**:

1. **Given** ゲーム実行中, **When** 左矢印キー長押し, **Then** ボードが画面端に到達するまで左に移動する
2. **Given** ゲーム実行中, **When** 右矢印キー長押し, **Then** ボードが画面端に到達するまで右に移動する
3. **Given** ボードとボールが接触, **When** ボールが落下中, **Then** ボールがボードに当たり、跳ね返される（反射角度は物理的に妥当）
4. **Given** ボードが移動中, **When** ボールと同時接触, **Then** ボードの移動速度がボール反射角度に反映される

---

### User Story 3 - ボール物理演算 (Priority: P1)

ボールは画面内で重力に従って落下し、壁やブロック、ボードと衝突して跳ね返ります。衝突判定が正確で、ボールが画面外に落ちないよう制御されます。

**Why this priority**: ゲームメカニクスの中心。ボールの挙動がなければ、他のすべての機能が無意味。

**Independent Test**: ボールを初期化し、落下、壁衝突、跳ね返りが正しく動作することを単独で検証。

**Acceptance Scenarios**:

1. **Given** ゲーム開始, **When** 初期フレーム, **Then** ボールが落下を開始する（重力が機能）
2. **Given** ボールが移動中, **When** 画面の上下左右の壁に接触, **Then** ボールが適切に跳ね返される
3. **Given** ボールがブロックに接触, **When** 接触フレーム, **Then** ボールが跳ね返り、ブロックのダメージカウンターが増加する
4. **Given** ボールの速度, **When** 計算, **Then** フレームレート依存ではない安定した移動速度（DeltaTime使用）

---

### User Story 4 - ブロック破壊とダメージシステム (Priority: P1)

ブロックは2度ボールに当たるとしか壊れません。最初の衝突でブロックは視覚的に変化し（例：色が薄くなる、ダメージインジケータ表示）、2度目でブロックが消える。

**Why this priority**: スコアリング、ゲーム進行、レベルアップはすべてブロック破壊数に依存。このシステムがないと、他の進行機構が動作しない。

**Independent Test**: ブロックに複数回衝突させ、1度目は生存確認、2度目で消滅確認。スコア加算のタイミング。

**Acceptance Scenarios**:

1. **Given** ブロック初期状態（完全体）, **When** ボール衝突1回目, **Then** ブロック見た目が変化（ダメージ状態）、スコア+1、ブロックはまだ存在する
2. **Given** ブロック（ダメージ状態）, **When** ボール衝突2回目, **Then** ブロックが消滅、スコア+1、ボールが跳ね返る
3. **Given** スコア加算後, **When** 5個のブロック破壊完了, **Then** レベルアップが発生
4. **Given** ブロック一覧, **When** 画面描画, **Then** ブロックの耐久度（1/2）がUI上で正確に表現される（色、アイコンなど）

---

### User Story 5 - スコアシステムと累積スコア表示 (Priority: P2)

プレイヤーが破壊したブロック数に応じてスコアが加算されます。各ブロック破壊時に1ポイント加算。スコアは画面に常時表示される。

**Why this priority**: ゲームの進行状況を視認するために必須。レベルアップ条件のベース。ただしP2は、ゲームが動く状態があれば、ブロック破壊のメカニクスより後で実装可能。

**Independent Test**: ブロック破壊アクションを複数回実行し、スコアが正確に増加、UI表示が同期することを確認。

**Acceptance Scenarios**:

1. **Given** ゲーム開始, **When** スコア表示確認, **Then** スコア初期値は0
2. **Given** ブロック1個破壊, **When** 破壊完了（2度目衝突）, **Then** スコア+1（表示は即座に更新）
3. **Given** 複数ブロック破壊後, **When** スコア確認, **Then** スコア = 破壊完了ブロック数
4. **Given** スコア表示, **When** ゲーム実行中, **Then** フォントサイズ・色が視認可能（WCAG基準）

---

### User Story 6 - レベルアップシステム (Priority: P2)

ブロック5個破壊するたびに、レベルが1上昇します。レベルが上昇するたびに、ボールのスピードが約10%増加します。

**Why this priority**: ゲームの難易度調整と進行感。P2は、基本ゲームメカニクスが動いてから実装。

**Independent Test**: スコアを0から5、10、15と進めながら、レベルアップと速度変化を検証。

**Acceptance Scenarios**:

1. **Given** ゲーム開始（レベル1）, **When** ブロック5個破壊, **Then** レベル2に昇格、画面にレベルアップ通知が表示される
2. **Given** レベル昇格時, **When** ボール速度確認, **Then** 前レベルの約110%の速度になる（正確性: ±5%以内）
3. **Given** 複数レベルアップ後, **When** 速度計測, **Then** 累積で正確に計算される（丸め誤差なし）
4. **Given** レベル表示, **When** 更新後, **Then** UI上に即座に反映（「Level: 2」等）

---

### User Story 7 - ライフシステムとゲームオーバー (Priority: P1)

プレイヤーは初期ライフ3を持ちます。ボールが画面下部に落ちるたびに、ライフが1減少します。ライフが0になると、ゲームオーバー画面が表示され、ゲームが終了します。

**Why this priority**: ゲーム失敗条件の実装。P1は、プレイヤーが何度かミスしてゲームが終わるまでの流れを実装・テストするため。

**Independent Test**: ボールを故意に落とし、ライフ減少を複数回確認。ライフ0でゲームオーバー。

**Acceptance Scenarios**:

1. **Given** ゲーム開始, **When** ライフ表示確認, **Then** ライフ = 3
2. **Given** ゲーム実行中, **When** ボールが画面下部に落ちる, **Then** ライフが1減少、画面に即反映
3. **Given** ライフ = 1, **When** ボール落下, **Then** ライフ = 0、ゲームオーバー画面へ遷移
4. **Given** ゲームオーバー状態, **When** 画面表示, **Then** 「Game Over」、最終スコア、レベルが表示される
5. **Given** ゲームオーバー状態, **When** 「Restart Game」ボタンをクリック、または R キーを押下, **Then** ゲームがリセットされ再開する

---

### User Story 8 - ゲームクリア条件 (Priority: P2)

8x8 = 64個のブロックがすべて破壊されると、ゲームはクリア状態になります。クリア画面が表示され、達成時間が表示されます。

**Why this priority**: ゲーム成功条件。基本メカニクス動作後に実装。

**Independent Test**: ゲーム進行中、ブロック数を監視し、64個破壊時にクリア遷移を確認。

**Acceptance Scenarios**:

1. **Given** ゲーム進行中, **When** 64個目のブロック破壊完了, **Then** クリア画面へ自動遷移
2. **Given** クリア画面表示, **When** 情報確認, **Then** 「Congratulations!」とプレイ時間が表示される
3. **Given** クリア画面, **When** 表示, **Then** 「Restart Game」ボタンでゲームをリスタート可能。R キーでもリスタート可能

---

### User Story 9 - 一時停止機能 (Priority: P3)

ゲーム実行中に P キーを押すことで、ゲームを一時停止・再開できます。一時停止中はボールやパドルが動作せず、「PAUSED」というメッセージが画面に表示されます。

**Why this priority**: プレイヤーの利便性向上。基本ゲーム機能完成後に実装。

**Independent Test**: ゲーム実行中に P キーを押し、一時停止状態の確認、再度 P キーで再開の確認。

**Acceptance Scenarios**:

1. **Given** ゲーム実行中, **When** P キー押下, **Then** ゲームが一時停止し「PAUSED」メッセージが表示される
2. **Given** ゲーム一時停止中, **When** P キー押下, **Then** ゲームが再開される
3. **Given** 一時停止状態, **When** 画面確認, **Then** ボールとパドルは動かず、表示のみされている

---

## Edge Cases

- **ボールが複数ブロックに同時接触**: 最初に計算された衝突のみを処理。他は無視。
- **ボードが高速移動中にボール衝突**: ボードの速度がボール反射角度に適用される。
- **ライフ0時にボール落下**: ゲームオーバー遷移で処理済み、二重実行なし。
- **レベルアップ中のボール衝突**: 速度変更はフレーム終了後に反映（パフォーマンス保証）。
- **画面端でボード・ブロック重複**: ボードは画面内に留まる。ブロックグリッドは固定。
- **クリア直前にボール落下**: クリア条件チェックが落下処理より先に実行される。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 8x8のブロックグリッドを初期化し、画面上部に配置すること。各ブロックは耐久度2を持つ。
- **FR-002**: System MUST ボールを毎フレーム物理演算で更新し、壁・ブロック・ボードと衝突判定を実施すること。
- **FR-003**: System MUST キーボード入力（左右矢印またはA/D）でボードパドルを制御可能にすること。
- **FR-004**: System MUST ボールがブロックに衝突するたびに、そのブロックのダメージカウンターを+1し、カウンター = 2で破壊すること。
- **FR-005**: System MUST ブロック破壊時にスコアを+1加算し、UI上に即座に更新すること。
- **FR-006**: System MUST スコアが5の倍数に達するたびにレベルを+1、ボール速度を約10%増加させること。
- **FR-007**: System MUST ボールが画面下部（y > 画面高さ）に到達したときに、ライフを-1し、ボールを初期位置にリセットすること。
- **FR-008**: System MUST ライフが0に到達したときに、ゲームオーバー画面へ遷移し、最終スコアとレベルを表示すること。
- **FR-009**: System MUST 全64個のブロック破壊でクリア画面へ遷移し、プレイ時間を表示すること。
- **FR-010**: System MUST P キーでゲームを一時停止・再開できること。一時停止中は「PAUSED」メッセージを表示すること。
- **FR-011**: System MUST ゲーム終了時（ゲームオーバーまたはクリア）に「Restart Game」ボタンを表示し、クリックまたは R キーでゲームをリセットできること。
- **FR-012**: System MUST 60FPS以上で安定したゲームループを実行し、フレームレート依存の移動を回避すること（DeltaTime使用）。
- **FR-013**: System MUST ボールが落下してリセットされても、現在のレベルに応じたスピード倍率を維持すること。

### Key Entities

- **Block**: `{ position: (x, y), health: 0-2, width, height, texture }` - ブロック。位置、耐久度、サイズ
- **Ball**: `{ position: (x, y), velocity: (vx, vy), radius }` - ボール。位置、速度、半径
- **Paddle**: `{ position: (x, y), width, height, speed }` - ボード。位置、サイズ、移動速度
- **GameState**: `{ score: int, level: int, lives: int, blockCount: int, gameOver: bool, won: bool }` - ゲーム状態

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ゲームは60FPS以上で安定して実行できること（フレームスキップなし）。
- **SC-002**: ボール衝突判定は誤差なく正確に実施される（衝突すべき範囲内で100% hit、範囲外で0% false positive）。
- **SC-003**: ボード操作のレスポンスラグは50ms以下（キー入力→画面表示）。
- **SC-004**: プレイヤーが平均的な難易度でゲームをクリアするのに3-5分の時間要する（適度なチャレンジ）。
- **SC-005**: UI要素（スコア、ライフ、レベル表示）はすべてWCAG 2.1 AA基準を満たすこと（色対比 4.5:1以上、フォント12pt以上）。
- **SC-006**: 新規ユーザー5名以上が初回プレイで、ゲームルールを理解でき、操作できること（ユーザーテストで評価）。
- **SC-007**: コードカバレッジ: 物理演算、衝突判定、ゲーム状態管理 = 80%以上。

## Implementation Notes

### 品質要件（憲法準拠）

**コード品質**:
- ゲームロジックは `GameEngine` / `PhysicsEngine` / `CollisionDetector` に分離（SRP）
- ボール、ブロック、ボードの各更新メソッドは独立してテスト可能
- 循環的複雑度: 各関数 < 10

**テスト基準**:
- Unit Test: 物理演算（速度、位置計算）、衝突判定（矩形・円衝突）
- Integration Test: ゲーム状態更新（スコア・ライフ・レベル）、入力→反映の流れ
- Manual Test: プレイヤーUXテスト（ユーザー5名以上）

**UX一貫性**:
- UI配置は統一（スコア左上、ライフ右上、レベル中央上）
- 色は背景とのコントラスト4.5:1以上を確保
- フォント最小12pt、見出し18pt以上
- ゲームオーバー/クリア画面はシンプルで分かりやすく
